# R2-first coverage expansion

This stage starts from commit `fc0e3deac2b3248b2dd84a9e88af88ecc744bb0b`, 59,270 published operational cameras and a 65,134-record private canonical master. `baseline.json`, verified immutable import receipts in `round*.json`, `summary.json` and `country-growth.csv` provide the measured changes. Counts describe source-backed devices/approaches/sections, not necessarily distinct physical poles.

New raw downloads and pre-dedupe observations reach private R2 before identity, geometry, country and publishing checks. Full accepted/candidate records and every duplicate/rejected disposition remain in R2. Only compact eligible canonical rows are appended to the existing Supabase production project. Existing full canonical records and operational fields are compared for preservation. LOW never automatically publishes. Country exports are immutable and checksum/count verified; the production manifest is published last through the existing signed backend.

The sources, licensing decisions and failed acquisition paths are in `source-discovery-audit.json`. A failed/blocked feed is not an empty dataset or proof of complete coverage. Generic CCTV, ALPR surveillance, speed feedback signs, road zones and violation counts are not counted as fixed enforcement cameras. Government ownership or a GitHub code license does not establish dataset reuse rights. Current OSM nodes/relations are independently refreshed against the primary API. Explicit average-speed endpoint roles and paired-device direction/speed/road rules remain intact; approximate way geometry remains LOW.

## Existing pipeline

- Acquire official feeds with `scripts/fetch_expansion_official.py` and regional OSM enforcement snapshots with `scripts/fetch_osm_extracts.py --countries REGION...`; `--countries` accepts the registered country/state/province codes. Geofabrik index URLs are independently verified. The Overpass tile alternative is `scripts/fetch_deep_osm.py`.
- `scripts/discover_coverage_catalogs.py --global-only` exhausts the global enforcement-service catalog without requiring the state name in item metadata. The additional `--global-extra` pass searches photo radar, photo enforcement, intersection safety and section control terms separately. Pagination, unique IDs and the declared total must agree; rights and camera purpose are subsequently checked per source.
- Large regional downloads use at most four parallel 8 MB ranges pinned to a dated URL and strong ETag; changed versions, truncated responses and incorrect ranges fail before acceptance. The private archive Worker streams into native R2 checksum validation, then the client verifies readback and restoration. Original official HTTP payloads are retained alongside parsed envelopes. Shared all-Ireland snapshots also produce a geofenced Northern Ireland partition without a second PBF download.
- Regional snapshots retain source URL, license, capture time, object IDs, versions, timestamps, tags and explicit relation members. Full PBF source bytes and the extracted camera observations are archived with per-file checksum/length and restoration checks before a normalized snapshot is offered to the importer. Verified local PBF/cache copies can be evicted; no application code/config is removed. Disk skips and transport failures are reported explicitly.
- Each batch also retains a compressed operational snapshot in private R2 before the append transaction; subsequent full-row comparison includes metadata. Read-only operational verification retries an interrupted PostgreSQL connection without replaying mutations.
- Each import freezes its source-file list and hashes; snapshots completed concurrently are deferred to the next batch.
- Run `scripts/expand_cameras.py`: archive source/pre-dedupe observations, primary OSM refresh, normalize, conservative dedupe against published **and candidate** records, private R2 full-master/observations/candidates archive, compact append-only PostgreSQL publication, verified public R2 export and manifest.
- Freeze the returned `master-db/storage/reports/latest-import.json` receipt as a numbered `round*.json` before another batch; run `scripts/report_coverage_stage.py` to verify unchanged baseline records and calculate cumulative growth.

All commands use the existing `.bootstrap-venv/bin/python` interpreter for Python scripts. Raw/cache/backups and credentials stay inside the project and are ignored by Git. Reports contain bounded samples and totals; complete dedupe/rejection rows live in ignored cache and private R2 rather than giant Git files.

## Recovery

Imports do not mutate existing canonical rows. Failed R2 checksum/count/restoration checks prevent PostgreSQL publication. A database commit with failed public delivery retains its pending-delivery marker for retry. Existing private R2 receipts and previous manifest backups permit restoration; see [../storage/ROLLBACK.md](../storage/ROLLBACK.md). Do not roll back by deleting source archives. This stage changes neither EAS configuration nor bundle/package identifiers, Supabase connection, or store/OTA releases.

New explicit multilingual enforcement fields distinguish speed, red light and combined devices. Official section reference points without both endpoints remain LOW review candidates. Taichung technology data has inverted coordinate labels verified against its separate section feed and inconsistent capability/address columns; all such records require review. Conflicting overlapping capabilities within five metres or unresolved differing direction labels are held for review; explicitly opposite headings remain distinct. Existing canonical records are unchanged.

Production manifests also include a compact public source catalog (agency/name, public source URL, country and licence), preserving attribution for official data alongside OpenStreetMap attribution. Full provenance and archive pointers remain private.

New OSM-only Texas red-light/combined points require review because the statewide prohibition retains contract exceptions; a mapped device alone cannot establish current operation. Current official operational evidence can be considered under the existing source policy. This guard affects new candidates only.

Overlapping OSM snapshots prefer the highest object version; richer metadata breaks ties only. Streaming whole-file restoration needs a local source plus compressed readback cache, rather than a third materialized source copy; the PBF pipeline streams archive input, verifies secret patterns across the full memory-mapped source, and evicts each local R2 shard after byte readback. Whole-file restoration then downloads bounded shards again and validates the original full SHA-256/length before accepting the manifest or deleting the source. Disk guards reserve the source plus at most 64 MB of shard cache and 200 MB headroom; the general downloader retains its conservative two-copy default. Insufficient space rejects before acceptance.

Some public Taiwan endpoints use a legacy CA extension rejected by Python 3.14's stricter X509 validator. Only the specific Missing Subject Key Identifier error permits the macOS system curl TLS stack fallback, with normal certificate-chain, hostname and expiry verification and HTTPS-only redirects; no insecure flag or authenticated download is permitted. Original bytes/checksums and transport metadata are retained. Other certificate failures remain fatal.
