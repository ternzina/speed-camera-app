# R2 operational storage rollback

Pause import writers and leave the public R2 country manifest serving existing clients. Never delete R2 archives during rollback.

The immutable root receipt and every table/file manifest are recorded in `master-db/storage/reports/migration.json` after completion. The local working copy is in ignored `master-db/backups/storage-architecture/prepared.json`. Read private archives through `scripts/r2_archive.py` using the local signing key; restore the key from the owner's credential backup if this machine is unavailable. The Cloudflare account owner can also restore access by generating a new Ed25519 key pair and rebinding the archive Worker to its public key: object hashes and archived bytes remain valid after key rotation. Private signing material must never enter GitHub or a public bucket.

1. Download the root receipt, original schema/access archive, full canonical/source observation tables and backup table manifests. Verify compressed and decoded SHA-256, exact row counts and original file hashes. `read_dataset` rejects missing/mismatched objects.
2. Recreate the original source observation table, sequence, constraints, indexes and private bootstrap functions from the archived schema. Enable RLS and restore only the archived grants/policies. The bootstrap role cannot perform administrative DDL; use the existing authorized Supabase migration connection.
3. Restore original full canonical rows by ID, merging rather than truncating the operational table, then restore source observations and optional legacy backup tables. Preserve all later published canonical rows, reports and moderation decisions. Apply subsequent immutable import receipts in registry order to recover post-migration observations/candidates; never replace newer moderation state with an older snapshot.
4. Reset sequences above the highest IDs, validate source foreign keys, all unique canonical/source identities, typed coordinates, active/confidence constraints, 49-country delivery and UA/PL legacy projections. The pre-cleanup drill restores every archived row into typed PostgreSQL temporary tables and compares full-row SHA-256 fingerprints for the large tables and every field for the smaller snapshots. The validated normalized master also hydrates the 1,323 legacy source links from the archived source catalog when pre-bootstrap `_source` metadata is absent.
5. Remove the private storage-control row only after switching the importer to the archived legacy ingest function, then resume writers. Public delivery can continue serving its unchanged R2 manifest throughout recovery.

Cleanup runs in one guarded transaction. If any precondition fails it rolls back automatically; no table is partially removed. A failure before cleanup needs no rollback. Objects are immutable and content-addressed; a failed future import may leave harmless orphan cold objects, but the committed master pointer advances only in the same transaction as successful canonical ingestion. Concurrent imports fail and must rebuild against the latest pointer.

Retention: no archive lifecycle/deletion rule is configured. Keep original snapshots, schema, receipt and signing-key recovery material until a later explicitly approved retention policy.
